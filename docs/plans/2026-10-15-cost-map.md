# 成本地图：费用结构化与每月固定成本总览

> 已并入总计划 [2026-10-15-ledger-and-cost-graph.md](2026-10-15-ledger-and-cost-graph.md)（对应 0.5 阶段）。金额类型已改为结构化 Money（十进制字符串 + 资产代码），取代下文的 number 方案。本文件保留作阶段 1–3 的细节参考。

目标：让 Atlas 回答"每月固定要花多少、花在哪些项目上"。订阅、服务器、域名、AI 额度的费用从文字变成可计算的数字，由程序汇总，不由模型计算。每天发生的流水账与 BTC 买卖不在本计划内，另立账本模块（见"不在本计划内"）。

## 背景与分界

- Atlas 管"约定"：有什么资源、彼此什么关系、预计花多少。这是会变的状态，可以修改。
- 账本管"实际发生"：某天实际扣了多少、收到多少。这是只增不改的流水。
- 现状：`subscription` 模板的 `cost` 是 text，没有币种与周期；Relation 只有 type 与 note，没有数字；没有任何汇总功能。已有的 `HOSTED_ON`、`DEPENDS_ON`、`PAID_BY`、`BILLED_FOR` 关联和 RENEWAL / PAYMENT_DUE 事件可以直接复用。

## 方案

### 阶段 1：费用结构化

- 在 subscription、server、domain、ai-provider-account 模板增加字段：`cost_amount`（number）、`cost_currency`（text，如 USD / JPY / CNY）、`billing_cycle`（monthly / yearly / usage）。
- 旧的 `cost` 文字字段保留不删，兼容旧库。
- 旧数据不静默迁移：`cost` 文字格式不统一（示例数据里只写 `monthly`，文档示例里有"八元"这样的中文数字，真实数据的写法未知），所以不做全自动解析。只识别简单明确的写法（如"8 USD/月"），作为 Proposal 进入待确认；其余保持原样并标为待整理，由用户手动补金额，或用一句话让模型提议，仍须确认。
- 模型边界不变：模型只提议字段值；金额、币种、周期在预览差异里突出显示，便于核对；无法确定的金额（如"十几块"）进入 uncertainty，不猜。

### 阶段 2：每月固定成本总览

- 纯本地计算，不经过模型：monthly 按原值，yearly 除以 12，usage（按量）单列、不折算。
- 按币种分别合计，不跨币种相加；没有汇率时分币种显示。是否引入汇率另行决定。
- 按项目分组：通过已有关联（HOSTED_ON、DEPENDS_ON 等）把资源归到项目；无法归属的归入"未归属"。
- 入口位置待定：主导航已收为首页、记忆、待确认、设置，倾向放在首页卡片或记忆页内的视图，不新增主导航项。

### 阶段 3：分摊与闲置容量（只做设计，先不实现）

- 需要在关联上存数字（占用比例），现有 Relation 无此字段。候选：Relation 增加可选 `share`（0–1），或独立的分摊记录。
- 规则：同一资源各项目比例之和不超过 100%，剩余部分记为"闲置容量"，不硬分给任何项目。
- 规则一经选定就要前后一致；这是人定的规则，不是计算得出的结论。
- 注意：改动 Relation 会影响同步的按记录三方合并、加密记录与备份兼容，需要单独评估。等阶段 1、2 实际使用一段时间后再决定。

## 约束

- 兼容旧库与旧 JSON；新增字段对旧版二进制的影响要说明，升级前提示导出加密备份。
- 不把真实清单、金额、账号写进仓库；测试和评测只用合成数据。
- 模型接口仍没有数据库写入权限；总数、折算、分组全部由本地代码完成。
- 金额用 number 存，汇总后按币种四舍五入显示；以后若出现精度问题，再改为最小货币单位整数。

## 文件

涉及 `src/lib/types.ts`（模板与字段）、`src/domain/proposal.ts` 与 `src/domain/changes.ts`（提案与差异预览）、Rust Vault 侧的字段校验。成本汇总建议新增独立的纯函数模块，便于单元测试。具体落点开工前核对，本文件不预设。

## 验证

- 前端逻辑测试：月度折算、年付除以 12、按量不折算、多币种分别合计、未归属项目、缺字段不报错。
- 扩充 `scripts/evaluate-local.mjs`：增加几条合成费用输入，如"某订阅月费 30 美元"、"域名年付 12 美元"、"费用大概十几块"（应进入 uncertainty），检查本地模型提案的金额、币种、周期。
- 旧库升级：用临时脱敏库验证旧 `cost` 文字被保留、解析提案可确认、可撤销。
- 不重跑与本计划无关的 OAuth、支付或完整 UI 套件。

## 不在本计划内

- **账本模块**：每笔实际收支、接单收入、BTC 买卖。原则：只增不改，写错补冲正记录；每笔带对应 Atlas 条目 ID 的引用；独立于实体表，不进入关联画布；BTC 的成本价与手续费随它一起设计。前置条件：先手动记两到三周，确认真正需要的字段，再动工。
- 汇率自动获取、外部服务同步、税务计算。

## 待确认

- 真实数据里 `cost` 的写法：加密库无法在仓库外读取，需在应用里看一眼订阅类条目，或导出脱敏数据查看。示例数据与文档已显示写法不统一，阶段 1 已按"不做全自动解析"处理。
- 成本总览放在哪里。
- 是否需要汇率，还是先分币种显示。
