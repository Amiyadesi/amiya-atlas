# 用一句话改动记忆

Atlas 0.2.1 的文字、剪贴板和语音入口共用 Capture / Proposal 管线。可以在一句话里同时新增、修改、停用或删除；模型只提议，事实仍须用户确认。

## 日常说法

| 输入                                         | 提案                                                         |
| -------------------------------------------- | ------------------------------------------------------------ |
| Saily 不用了，改用 3HK 香港备用号码。        | Saily 改为已停用，新增 3HK；保留 Saily 的字段、关联和提醒。  |
| 把 Saily 归档。                              | Saily 改为已归档。                                           |
| 从 Atlas 删除 Saily，另记 3HK 香港备用号码。 | 删除 Saily，新增 3HK；一并列出要解除的关联与移除的生命周期。 |
| 删除 Saily 的月费属性，其余保留。            | 只删除已有的月费字段，不删除号码。                           |
| 解除 Reddit Main 与 Saily 的找回关联。       | 只解除那条已存在的关联，保留两端记忆。                       |
| 取消 Saily 的复查提醒。                      | 删除已存在的复查事件，不删除 Saily。                         |
| 不要删除 Saily，把月费改成八元。             | 修改月费，不提出删除。                                       |

“放弃”“不用了”保留历史；删除须明确表达并指向可辨认的名称。同名对象、未说明的“这个”、不存在的字段或未知关联不能猜测 ID，请补充名称。取消续费与立即停用含义不同，“已付到某月，以后不续”仍记录到期和不续费策略。

## 确认页

默认先看到变更预览：绿色 `＋ 新增`、红色 `－ 删除`，修改同时显示旧值和新值。颜色之外还有文字、符号和语义化的插入 / 删除标记。旧值来自当前数据库；更新沿用实际提交的字段合并与备注追加规则，没有变化的字段不显示。

删除一项记忆会列出数据库中实际存在的相邻关联、生命周期；不会继续删除另一端的账号或服务。点击「取消此项」可只取消那项动作，取消实体删除也保留自动列出的关联和提醒。「修改提案」展开原有编辑控件；删除字段可单独取消。确认前实体、关联和事件都不改变。

如果预览后记忆库发生变化，删除操作必须重新理解，避免把后来新增的关联一起移除。普通更新也核对实体版本。原始 Capture 始终保留。

## 撤销

确认后提供「撤销这次变更」。一次撤销恢复本次修改 / 删除前的字段值、隐私标记、原始 ID、关联和生命周期，并移除本次新建内容；提案回到待确认，可以修改后再次提交。

最近一次确认的受影响记录保存在加密 Proposal 中，桌面重启和加密备份恢复后仍可撤销。只允许撤销当前最新版本：后续捕获、设置保存、确认或其他写入会使旧撤销失效，避免覆盖之后的工作。下一次确认替换旧撤销记录。此功能不是多步版本历史，也不承诺安全擦除；删除实体后，原始输入和最近一次加密撤销记录仍可能保留相关内容。

确认与撤销沿用 SQLite 事务，实体、关联、事件与提案状态整体提交。旧 Capture / Proposal 无删除字段时默认空数组，仍可读取。升级前导出加密备份，保存新版记录后继续使用新版。

## 模型与数据边界

新增记忆沿用原来的提取提示；变更输入使用更短的动作指令和增删并存示例。无需删除时，生成 Schema 不包含删除能力；包含删除时要求明确返回三个删除数组。受管理的本地模型使用 JSON 模式；完整 Zod 和 Rust 校验不变，原文、已知 ID、否定表达、字段与实体范围、版本及隐私在本地独立验证。

候选实体最多 12 个，只发送 ID、名称、类型和状态；删除类输入还发送最多 50 个非秘密字段名称 / 实体、30 条候选关联和 20 个事件的 ID、类型与日期。已有字段值和历史原文不发送。模型填出的未提供占位值（如“未知”）转为 uncertainty，保留旧值；用户原文明说未知时允许记录。SECRET 实体及拓扑不参与匹配；涉及秘密字段或隐藏关联的实体删除被阻止，可选择停用保留或手动处理。

## 验证与设计参考

28 条前端逻辑、20 条 Rust / SQLite 与 8 条浏览器测试覆盖混合增删、取消、否定、字段删除、解除关联、隐私边界、过期提案、事务保存、加密重启恢复与撤销。浏览器测试使用受控模型输出验证交互；真实本地模型评测独立运行，不能将浏览器模拟当作模型准确率。

`node scripts/evaluate-local.mjs` 检查 13 条 Capture 和 2 条查询：原来的七条记忆输入，加上停用并新增、删除并新增、字段删除、取消提醒、解绑与否定删除。采用合成邮箱和测试关联，不上传用户真实清单。评测产物在忽略的 `qa-artifacts/` 中，任一断言失败返回非零状态。指定单项可执行 `node scripts/evaluate-local.mjs delete`。

实现参考 [GitHub 变更审查](https://docs.github.com/en/get-started/start-your-journey/reviewing-your-proposed-changes)、[W3C 颜色之外的文字提示](https://www.w3.org/WAI/WCAG22/Techniques/general/G14) 和 [SQLite 事务](https://www.sqlite.org/lang_transaction.html)。后续优先用真实输入衡量纠错成本和确认速度，再考虑更多关系类型与多步历史。

## 0.2.1 本地模型验证（2026-10-07）

默认调整为 Qwen3.5 4B Q4_K_M，使用 JSON 模式与本地完整校验。已有模型选择不自动覆盖，不在后台下载另一份模型；旧库保存了 2B 设置时可在设置选择推荐 4B。

| 配置                            | 指定断言 | 观察                                                 |
| ------------------------------- | -------- | ---------------------------------------------------- |
| 2B，JSON 模式                   | 12 / 15  | 更快，但删除并新增、仅取消提醒和仅解绑仍失败。       |
| 4B，Schema 约束                 | 14 / 15  | 混合增删正确；字段移除漏掉结构化删除键。             |
| 4B，JSON + 未提供值转为不确定项 | 15 / 15  | 保留旧值、字段移除、解绑、提醒、否定和混合增删通过。 |

这是同一开发环境、相同指定输入与最终断言的小样本；关闭思考、temperature 0、seed 42、8 线程、4096 上下文，预加载模型。没有将 15 条通过当作通用准确率。4B 的最终 13 条 Capture 计时包含系统提示重新预填，复杂变更在这台 CPU 上仍可能超过 15 秒；实际体验需要在目标电脑验证。2B 保留为轻量选项，复合变更需仔细检查。没有把未提供的字段值当作事实，也没有降低提交校验。

对生成方式的比较参考了 [The Constraint Tax](https://arxiv.org/abs/2605.26128) 对小模型语义准确性与格式正确性的区分；该预印本不是对 Atlas 所用模型的验证，本项目结论来自上述实际输入。Ollama 的 [Chat API](https://docs.ollama.com/api/chat) 同时支持 JSON 与 Schema 格式；已有 Ollama / 兼容服务仍遵循配置的格式，受管理的 Atlas Local 固定采用本版测试的 JSON 预设。

比较输出格式时可设置 `ATLAS_EVAL_MODEL`、`ATLAS_EVAL_FORMAT`（`json_schema` / `json_object` / `prompt`）与 `ATLAS_EVAL_THREADS`。指定格式会用普通 Ollama 路径比较，默认路径验证 Atlas Local 的受管理预设；输出目录包含模型、线程数和格式。
